# Welcome to the Sunny Side – Site Reference

A static, terminal-driven personal website: plain HTML pages generated by one
Node build script, a little vanilla JavaScript, Tailwind CSS, and an xterm.js
terminal. Deployed to GitHub Pages.

This file documents how the site works. For the rules to follow when editing
it, see `CLAUDE.md`.

---

## 1. Overview

- **Content** is `src/content/**/*.{md,html}`. Each file is a page; `.md` files
  are shown as `.html` (`src/content/algo/theory/sais.md` → `/algo/theory/sais.html`).
  Together they form the **virtual file system (VFS)** that the terminal
  browses and the index pages list.
- **`build.js`** turns that into `dist/`: one static HTML file per page (math
  already typeset, SVG figures inlined), one index page per directory, the
  CSS, the JS, and a few extras for crawlers and agents.
- **In the browser**, every page arrives complete and skinned. `src/client/`
  adds client-side navigation (fetch the next page, swap its content in), the
  terminal, the mobile breadcrumbs' skin toggle, and a few touch-ups.

`/` is the home page (the browser shows it as `/home.html`).

## 3. Build

`node build.js` (`npm run build`) does everything, in ~4 seconds:

1. Copies `public/` to `dist/`.
2. Scans `src/content/` (`src/build/vfs.js`) into a page list, a tree and a
   map of dates.
3. Builds `dist/site.css`: Tailwind (as a PostCSS plugin) over
   `src/styles/global.css`, followed by xterm.js's CSS, `terminal.css`, and
   generated rules (terminal themes, home backgrounds); then esbuild bundles
   the `@import`s, minifies, and adds vendor prefixes.
4. Bundles `src/client/` with esbuild into `dist/js/` (`site.js`, plus chunks
   loaded on demand). The VFS tree and dates are compiled in as `VFS_TREE` /
   `VFS_DATES`.
5. Writes every page through the shell in `src/build/templates.js`:
   - markdown pages: rendered (§5), with a blog header if `displayMode: blog`;
   - raw `.html` pages: inserted as they are (§6);
   - one index page per directory (`/algo/index.html`, ...);
   - the home page, as both `/index.html` and `/home.html`.
6. Writes `/<path>.md` (each markdown page's source), `/llms.txt` and
   `/sitemap.xml` (§11).

CSS and `site.js` are linked with a content hash (`/site.css?v=…`), so a
deploy never serves new pages with stale assets; esbuild's chunks have the
hash in their names.

**The root listing.** `/` and `/index.html` are both served by
`dist/index.html`, which is the home page. The root directory listing (what
`open /index.html` and the `~` breadcrumb show) is written to
`dist/root-index.html` instead; the router fetches it for `/index.html`, and
also swaps it in when `/index.html` is loaded directly.

## 4. Pages in the browser

### The shell

Every page has the same frame (`shell()` in `templates.js`): a CSS grid with
the mobile breadcrumb bar, `<main>` (the content pane) and `<aside>` (the
terminal pane, desktop only).

**Mobile scrolling.** Below `md` (768px) the *document* scrolls: the grid is
`min-h-[100dvh]` and `main` grows; the breadcrumb bar is `sticky top-0`. From
`md` up the grid is `h-screen` and `main` is the scroll container beside the
terminal. Why: on iOS WebKit, scrolling a math-heavy `main` that also holds
nested horizontal scroll areas (code blocks, spoilers) lagged badly on the
SA-IS post, while Android/Blink was fine. Any one of these fixed it in
on-device tests: document scroll, removing the nested scrollers, removing the
math, or `content-visibility: auto`. The hidden assistive MathML was not the
cause. The scrollbar styles in `global.css` target both `main` and `html` for
this reason. `scrollbar-color` is inherited, so the terminal's viewport sets
its own (from the terminal theme, `terminal.css`); otherwise it would wear the
content skin's. Where `scrollbar-color` is supported (Chrome 121+, Firefox) it
overrides the `::-webkit-scrollbar` rules, which only matter for Safari.

### Client-side navigation (`src/client/router.js`)

After the first load the page never reloads. `push(path)` — called by the
terminal's `open`/`pop`, the breadcrumbs, and clicks on any same-site link to
a VFS page — does `pushState`, fetches the target's static HTML, and swaps its
`<main>`, breadcrumb `<nav>`, `<title>` and head metadata into the document.
So a page looks the same whether it was loaded directly or navigated to:
there is only one rendering of it, the static file.

- The old content stays visible until the new page has arrived.
- Pushed navigations fire `site:navstart` / `site:navend` on `window`; the
  terminal shows a spinner and locks input in between. Back/forward swap
  silently.
- New pages start at the top; back/forward restore the scroll position
  (kept in `history.state`).
- After every swap (and once at startup) `site:load` fires. `site.js` uses
  it to localize blog dates, re-break overflowing display math (§5) and
  typeset raw pages that need client MathJax (§6).

### Skins (`cskin`) — `src/styles/skins.css`, `src/client/skin.js`

Two skins, `dark` (default) and `sunny`. A skin is a block of CSS variables on
`<html data-skin="…">`; Tailwind's colour, font-size, spacing, radius and
easing tokens point at them (`tailwind.config.js`), so a skin restyles
everything without rebuilding. Skin-specific *classes* use Tailwind's `dark:`
variant, which `tailwind.config.js` keys on `[data-skin="dark"]` (e.g. dark
inverts `prose` and sets long-form text in Plex Sans). Tailwind only
generates classes it finds written out literally in `src/**/*.{js,html,md}`,
so never build class names by concatenation.

An inline script at the top of each page (`PREPAINT` in `templates.js`) puts
the saved skin (`localStorage` `wtss-skin`), terminal theme and terminal
collapse state on `<html>` before the first paint, so pages never flash the
wrong colours. `wearSkin()` in `skin.js` is the only other place that changes
the skin.

- Prose colours come from the skin, not the typography plugin's greys:
  `tailwind.config.js` maps `--tw-prose-{body,headings,bold,code,bullets,counters}`
  (and their `-invert-` twins) to `--text`, `--title`, `--text-muted`. Every
  skin must define `--title`.
- Font sizes `fs-{xs,sm,base,lg,xl,2xl}` are per skin (sunny = dark ×1.11);
  their line heights are unitless and shared, set in `tailwind.config.js`.
  Plex Sans runs larger than sunny's serif at the same size, so sunny's
  `--prose-font-size` (1.11rem) is ~1/0.9× dark's (1rem) to keep the two
  visually matched.
- The dark skin sets headings, paragraphs, list items, blockquotes and table
  cells of blog articles (and musings posts) in IBM Plex Sans; code, post
  date/tags and the terminal stay in IBM Plex Mono.

### Mobile navigation

The terminal is hidden below 768px (and xterm.js is never even downloaded
there). In its place, the breadcrumb bar (`breadcrumbs()` in `templates.js`)
shows the current path; each parent segment opens that directory's index
page, and the ☾/☀ button cycles skins. Index pages list a directory with tree
glyphs; their entries are real links.

### Home page

The home page is a full-pane background image chosen per skin and device by
CSS that `build.js` generates from `public/assets/home/active/<skin>/<pc|mobile>/`
(the first image in each folder, by name; `mobile` applies below 768px). Only
the matching image is downloaded.

## 5. Markdown pages

1. Drop a `.md` file anywhere under `src/content/` (never `index.md`: index
   pages are generated, and the build refuses the collision).
2. Optional frontmatter:

   ```yaml
   ---
   title: My Post
   date: 2025-06-14
   tags: [algorithm]
   displayMode: blog        # blog header (title, date, tags) and blog styling
   ---
   ```

   Without `displayMode: blog` the page gets plain prose styling. `title` is
   used for the tab title and the blog header; `date` for the header and the
   terminal's date sorting.

### Rendering pipeline (`src/build/render.js`)

- **Frontmatter** is parsed by a tiny parser (`src/build/frontmatter.js`):
  `key: value`, quoted strings, one-line `[a, b]` lists. That is all the
  content uses; no YAML library needed.
- **markdown-it** (`src/lib/markdown.js`, a shared singleton — do not build a
  second instance): raw HTML allowed, linkify on; highlight.js with only C++
  registered (aliases `cpp`, `c++`, `cc`, `cxx`, `hpp`, `hxx`), other fences
  escaped. Pseudocode fences (`pseudo`) get no grammar, but `#` comments are
  wrapped in `<span class="pseudo-comment">` (green, in `global.css`). A small
  inline-rule plugin wraps `$…$`, `$$…$$`, `\(…\)`, `\[…\]` as raw HTML so
  markdown-it doesn't read `_` inside math as emphasis.
- **Math is typeset at build time** (`src/build/typesetMath.js`): MathJax 4 in
  Node (`@mathjax/src` + `@mathjax/mathjax-newcm-font`, liteDOM, assistive
  MathML) returns a `<style>` block with the page's CHTML rules followed by the
  typeset HTML. Fonts load from jsDelivr, pinned to the installed font
  version. Phones never download or run MathJax for these pages; client-side
  typesetting of the SA-IS post (~500 expressions) used to show raw TeX for
  seconds and made mobile scrolling lag. The TeX packages loaded mirror the
  CDN build's defaults plus everything it would autoload.
- **SVG figures are inlined after math** (`src/build/figures.js`). A page
  places a figure with an empty placeholder, usually inside a `<figure>`:

  ```html
  <div class="svg-figure" data-svg="sais/slope-view.svg" role="img" aria-label="..."></div>
  ```

  The build pastes `src/figures/sais/slope-view.svg` into it (a missing file
  fails the build). The order matters: MathJax would read the `$` in figure
  text (e.g. the sentinel in `baacbcbacbccdaa$`) as math. Inline SVG (unlike
  `<img>`) is styled by the page: each folder of `src/figures/` is one figure
  set with a `palette.css` setting its `--fig-*` colours and fonts per skin,
  keyed on `<html data-skin>`. It is inlined once, before the page's first
  figure from that folder, so figure colours stay out of the skins, follow
  `cskin` instantly, and pages without figures carry no extra CSS. A new skin
  needs a block in each figure set's palette, or its figures render in
  browser defaults. Figures have no background; `.svg-figure svg` in
  `global.css` scales them to the column. Don't add skin-specific PNG figures.
  The SA-IS SVGs are generated by Python scripts in `bs/sais/claude/`
  (gitignored, local only): e.g.
  `python3 bs/sais/claude/slope_view.py src/figures/sais/slope-view.svg [preview-dir]`.
- **Display-math re-breaking.** Line breaks inside inline math survive the
  build, but breaking a long display equation needs the real column width.
  Each display `mjx-container` keeps its TeX in `data-tex`, and
  `rebreakDisplayMath()` (`src/client/mathjax.js`) re-typesets only the ones
  that overflow, on load and when a `<details>` spoiler opens. Pages where
  everything fits never load MathJax.
- **Description.** `<meta name="description">` is the first paragraph of 40+
  characters of markdown-it's output (before typesetting, so math reads as
  TeX), cut to 160 characters.

### Custom elements

Raw HTML with styling hooks from `src/styles/custom-elements.css`:

- `<details><summary class="spoiler-summary">…</summary><div class="spoiler-content">…</div></details>`
- `<div class="theorem-box">…</div>`
- `<ul class="outline-list">…</ul>`

Long lines (e.g. LaTeX) scroll horizontally inside spoiler and theorem boxes
instead of widening the page.

## 6. Raw HTML pages

A `.html` file under `src/content/` is a page as is: the build drops its
`<!DOCTYPE>`, `<html>`, `<head>` and `<body>` tags (it lives inside the content
pane, and browsers ignored those there anyway) and puts the rest in the
content pane, where it inherits the skin and Tailwind's classes.

- **Scripts.** On a direct load they run as the page parses. After in-place
  navigation the router re-creates each `<script>` in order, waiting for
  external ones, so they run again on every visit. Module scripts run only
  once per page lifetime; a page using one should also do its work on the
  `site:load` event (see `src/client/musings.js`).
- **Math.** Raw pages aren't typeset at build time (arbitrary HTML may not
  survive MathJax's parser). If the page's text contains math delimiters, the
  client loads MathJax and typesets the content pane.
- **Date.** `<meta name="wtss:date" content="YYYY-MM-DD">` feeds the
  terminal's `ls -d`/`-v`, like frontmatter `date` does for markdown.
- No `.md` copy, no meta description; the tab title is the file name.

Current pages: `/misc/cf-archiver.html` (Codeforces AC archiver: JSZip + Web
Crypto) and `/misc/void.html` (musings, §9).

## 7. Terminal

`src/client/pane.js` owns the desktop pane: it loads `terminal.js` (and
xterm.js with it) only once the pane is visible, collapses/expands it, and
handles the global shortcuts. `src/client/terminal.js` is the terminal: an
xterm.js instance, a line editor of its own (history, ghost-text completion,
cursor movement, line wrapping) and the commands. It reads the VFS from
`src/client/vfs.js`.

### Commands

| Command | Description |
|---|---|
| `ls [-r] [-d\|-dl\|-de] [-v] [path]` | Tree listing. `-r` recursive, `-d`/`-dl` newest first, `-de` oldest first, `-v` show dates |
| `cd <dir>` | Change directory (relative or absolute) |
| `open <file>` | Open a page in the content pane |
| `pop` | Go back to the previous page opened from the terminal |
| `clear` | Clear the terminal |
| `cskins` / `cskin <name>` | List / set the content skin |
| `tskins` / `tskin <name>` | List / set the terminal theme |
| `help` | Command and shortcut list |

### Keyboard

| Shortcut | Purpose |
|---|---|
| `Tab` | Accept the autocomplete suggestion |
| `Shift + Tab` | Cycle suggestions |
| `↑ / ↓` | Command history |
| `← / →` | Move the cursor |
| `Ctrl + Backspace` | Delete the previous word |
| `Shift + →` | Collapse the terminal pane |
| `Shift + ←` | Expand / focus the terminal pane |
| `Shift + ↑` | Leave the terminal (focus the content pane) |
| `h` / `j` / `k` / `l` | Scroll the content pane (when nothing editable has focus) |

Collapsing is keyboard-only. (The old site had a collapse tab, but the pane's
`overflow: hidden` always clipped it.)

### xterm.js gotchas

Things in `terminal.js` that look simplifiable but are not:

- **`onKey` and `onData` fire alongside each other**, not as alternatives.
  `preventDefault()` in `onKey` only blocks the browser's default; the data
  callback still receives the keystroke. Escape sequences (`\x1b[Z` for
  Shift+Tab, `\x1b[A/B/C/D` for arrows) reach `writeChar` as data, so the
  `escSeq` parser there must consume them or they get inserted as text.
- **Cursor escapes do not wrap across visual rows.** `\x1b[D` / `\x1b[C` stop
  at column boundaries. Backspace at column 0 of a wrapped row is handled
  specifically (up one row, last column, clear forward); Ctrl+Backspace
  redraws from the prompt's row. Fix line-boundary bugs by handling the
  boundary case, not by rewriting the editing functions.
- **Cell size is measured once, at open.** `mountTerminal` waits for IBM Plex
  Mono to load first; otherwise the grid is sized for the fallback font and
  line spacing varies between loads.
- **Font size** is a JS number (`fontSize` in the xterm options), read once
  from the root font size; it doesn't follow the `clamp()` on `html` live.
- **Ctrl/Cmd passthrough.** The custom key handler lets browser shortcuts
  (Ctrl+R, Ctrl+L, Ctrl+F, ...) bypass xterm.
- **Bottom padding.** `fitWithPadding()` leaves breathing room so the cursor
  doesn't hug the edge.

### Terminal themes (`tskin`) — `src/client/terminalThemes.js`

Independent from the content skins (a light terminal beside a dark page is a
normal combination). Five themes: `classic` (default), `solarized`,
`gruvbox`, `dracula`, `nord`. Each has:

- `xterm` — xterm.js's palette;
- `ui` — the colours the terminal writes itself (prompt path, files, dirs);
- `wrapper` — the pane's border, glow, shadow and background.

`build.js` turns each theme into a CSS rule setting the pane's `--tp-*`
variables on `<html data-tskin="…">`, so the pane is drawn in the saved theme
(`localStorage` `wtss-terminal-theme`) before any JS runs. Switching themes
clears the terminal so old output doesn't keep stale colours.

## 8. Fonts and scale

- IBM Plex Mono and IBM Plex Sans load from Google Fonts (`global.css`);

- Global scale is `html { font-size: clamp(16px, calc(0.5rem + 0.8vw), 22px) }`

## 9. Musings (`/misc/void.html`)

A stream of short posts; some are public markdown, others AES-GCM encrypted
blobs that decrypt in the browser with a passphrase.

- **Sources** are in gitignored `misc_assets/musings_src/` (one `.md` per post,
  plus `key.txt`). `tools/musings/main.py` writes
  `public/musings/manifest.json` and `public/musings/data/*.json`. Private
  posts use scrypt (N=32768, r=8, p=1) and AES-256-GCM with AAD
  `musings:<id>:v1`.
- **Idempotent re-encryption.** Encryption is randomized (fresh salt and IV),
  which would change every blob and the manifest on every rebuild.
  `try_reuse_private_blob()` decrypts the committed blob first and, if the
  plaintext is unchanged, reuses its ciphertext. This is safe: the same key
  and IV only ever encrypt the same plaintext (no GCM nonce reuse), and a
  missing, corrupt or re-keyed blob falls back to a fresh encryption.
- **Page.** `void.html` is a plain HTML content page: an empty `#musings`
  element and `<script type="module" src="/js/musings.js">`.
  `src/client/musings.js` fetches the manifest, shows posts 12 at a time
  (infinite scroll), fetches each post's blob as it nears the viewport,
  renders markdown with the shared renderer and typesets math with client
  MathJax. Private posts show a ciphertext preview until decrypted.
  `#musings` is itself a `prose` element because Typography's list spacing
  rules need the post list to be a direct child of one.
- **Decryption** runs in `src/client/musingsWorker.js`, so the decrypt
  button's shuffle animation stays smooth. The passphrase lives only in the
  page's input, never persisted.

## 10. Parked: sunny recolour of the dark home image

Tried 2026-10-16 and frozen; sunny still uses its own home image
(`active/sunny/`). Script kept at `tools/experiments/home-bg-tritone.py`
(usage in its docstring).

- **Goal:** give the sunny skin a version of the dark home image
  (`expoutput-1500w.webp`) in the sunny palette. Two directions: a "vanilla"
  port (same light/dark layout) and an inverted, "dark heaven cyberpunk" port.
- **Key finding:** the dark image is a *tritone*: solid black, bright teal,
  and scanlines that are a dark shade of the teal, not black. A two-colour
  (duotone) map sends scanlines and solids to the same dark, and the scanline
  areas average into mud. Mapping the three luminance stops (about 0 / 37 /
  230) to three colours keeps the original's clean look.
- **Best result:** "v4", vanilla: solid `#2A1A0A`, scanlines `#D9A441`, light
  `#FAF8F4`. Inverted favourites were "i1" (solid `#F6F2EC`, scanlines
  `#8A520F`, dark `#121110`) and "i4" (`#F6F2EC`, `#6A3C08`, `#0B0907`).
- **Why it stalled:** v4's light areas average out to tan (about `#EAD09F`),
  clearly darker than the blog background `#F6F2EC`. Lightening it (paler
  scanline colour, and/or reaching cream earlier in the luminance ramp so the
  lines thin out) made the image look rough and patchy in places, already at
  "v4c" (scanlines `#E6BF73`, cream reached at L150). Untested guess: the
  steep ramp is amplifying compression noise in the source webp's teal fields.
- **Ideas if resumed:** start from a less-compressed or higher-resolution
  master; smooth or denoise the luminance before mapping; or keep v4's colours
  and lighten with a cream overlay in CSS instead of changing the ramp. The
  mobile image (`mobileoutput1.jpg`) was never converted.

## 11. Crawlers and agents

- **Static content.** Every page's HTML contains its full content, `<title>`,
  description and canonical URL (on `https://www.welcome-to-the-sunny-side.com`),
  so crawlers, link previews and agents need no JavaScript. Index pages use
  real links.
- **`/sitemap.xml`** lists every page; `public/robots.txt` points at it. The
  live domain's `robots.txt` is fronted by Cloudflare's managed
  content-signals block; ours is appended after it.
- **Markdown copies.** Each markdown page's source is also served at the same
  path with `.md` (`/algo/theory/sais.md`). Rendered HTML is a poor read for
  agents: MathJax output turns into doubled text (`𝑇𝑖Ti` for `T_i`), inline
  SVG becomes label soup, and the page is ~10× larger. Pages point to the
  copy three ways: a visible line in the blog header ("Raw Markdown for this
  page can be found here." — the only one agents that just fetch the HTML
  see, since fetch tools drop `<head>`), `<link rel="alternate"
  type="text/markdown">`, and `/llms.txt` (llmstxt.org), which lists them
  all. Don't use hidden on-page text telling agents to go elsewhere: careful
  agents treat it as prompt injection, and search engines as cloaking.

## 12. Develop, check, deploy

```bash
npm install
npm run build    # → dist/
npm run serve    # http://localhost:4321 (static server for dist/)
npm run dev      # build + serve; rebuild by hand after changes (no live reload)
npm run deploy   # build + push dist/ to the gh-pages branch
```

**Visual regression check** (`tools/shots.mjs`, needs Playwright; in the
Claude Code cloud container run with `NODE_PATH=/opt/node-tools/node_modules`):

```bash
node tools/shots.mjs capture /tmp/before   # on the old build
node tools/shots.mjs capture /tmp/after    # after the change (rebuild first)
node tools/shots.mjs compare /tmp/before /tmp/after
```

It screenshots every page in both skins (desktop viewport, desktop content at
full height, mobile) plus scripted terminal and mobile-navigation sessions,
and pixel-diffs two captures (diff images in `<after>-diff/`). Known noise:
about 10 pixels on most desktop shots, the sunny table on
`algo/misc/good_problems.html`, and the terminal right after `clear`, all of
which vary between runs of the same build.

## 13. Troubleshooting

| Symptom | Likely cause |
|---|---|
| A page is missing | No source under `src/content/`, or not `.md`/`.html` |
| Build fails on `index.md` / `index.html` | Directory index pages are generated; rename the file |
| Build fails with "figure not found" | Wrong `data-svg` path, or the set has no `palette.css` |
| A Tailwind class has no effect | It isn't written out literally in `src/**/*.{js,html,md}`, so Tailwind never generated it |
| Inline math like `$a_{i}$` shows italics | The source is outside a delimiter the math plugin knows (`$…$`, `$$…$$`, `\(…\)`, `\[…\]`) |
| Math renders as raw TeX or errors | It's typeset at build time: check the build output, and that `typesetMath.js` loads the TeX package the macro needs |
| Long display math overflows on mobile | `rebreakDisplayMath()` should re-break it; an unbreakable token needs rewriting in the source |
| A raw HTML page's script breaks on the second visit | Top-level `let`/`const`/`class` in a classic script are declared again; wrap the script in a block or an IIFE |
| Terminal input misbehaves at line wrap | See the xterm.js gotchas (§7) |
| Terminal line spacing is off | The cell size was measured before the font loaded (§7) |

- **New terminal command** — add a `case` to `exec()` in `src/client/terminal.js`,
  add it to `COMMANDS` (completion) and the `help` output, and update §7.
- **New skin** — add a block to `src/styles/skins.css` defining every variable,
  add its name to `SKINS` in `src/client/skin.js` and to the pre-paint check
  in `templates.js`, and give each figure set's `palette.css` a block for it.
  Skin-specific classes beyond dark/not-dark would need another Tailwind
  variant in `tailwind.config.js`.
- **New terminal theme** — add an entry to `src/client/terminalThemes.js`
  (all three sections) and to `THEMES`.
- **New home background** — replace the image in
  `public/assets/home/active/<skin>/<pc|mobile>/`.
