I thought of this idea while solving 1957F2. It is extremely easy, cute (at least compared to the official solution), and can be generalized, so I'll share it here.

Problem

Given two sets of vertices 𝑋X and 𝑌Y and a boolean function 𝑓 :𝑋 ×𝑌 →{0,1}f:X×Y→{0,1}, we define a bipartite graph 𝐺 =(𝑉 =(𝑋 ∪𝑌),𝐸 =((𝑢,𝑣) ∣𝑢 ∈𝑋,𝑣 ∈𝑌,𝑓(𝑢,𝑣) =1))G=(V=(X∪Y),E=((u,v)∣u∈X,v∈Y,f(u,v)=1))

We need to find 𝑘k adjacent vertices in 𝐺G for every node 𝑢 ∈𝑋u∈X.

Solution

Requirements

  1. We can compute 𝑓(𝑢,𝑣)f(u,v) in 𝑂(𝑥)O(x) time.
  2. We can construct a data structure 𝐷(𝑍)D(Z) from some subset 𝑍 ⊆𝑌Z⊆Y in 𝑂(𝑝(|𝑍|))O(p(|Z|)) time, such that we can query if there exists some 𝑣 ∈𝑍v∈Z such that 𝑓(𝑢,𝑣) =1f(u,v)=1 in 𝑂(𝑞(|𝑍|))O(q(|Z|)) time.

Algorithm

Definitions
  • 𝑛 =|𝑋|n=|X|
  • 𝑚 =|𝑌|m=|Y|
  • Let 𝑄(𝑢,𝐷(𝑍))Q(u,D(Z)) be the query function which checks if there exists some 𝑣 ∈𝑍v∈Z such that 𝑓(𝑢,𝑣) =1f(u,v)=1.

We will use block decomposition with 𝐵B as the block size. The algorithm works in the following way:

  1. Divide 𝑌Y into ⌈𝑚/𝐵⌉⌈m/B⌉ disjoint subsets of size 𝐵B. Let the 𝑖i'th subset be 𝑆𝑖Si
  2. Iterate over the subsets, while maintaining a list 𝐿L of all 𝑢 ∈𝑋u∈X for which we have found <𝑘<k neighbors till that point of time (𝐿 =𝑋L=X initially).
  3. At subset 𝑆𝑖Si, we will do the following:
    1. Construct 𝐷(𝑆𝑖)D(Si).
    2. Create an empty list 𝐻𝑖Hi, and add 𝑢u to 𝐻𝑖Hi (also delete it from 𝐿L) for all 𝑢 ∈𝐿u∈L such that 𝑄(𝑢,𝐷(𝑆𝑖)) =1Q(u,D(Si))=1.
    3. Compute 𝑓(𝑢,𝑣) ∀ 𝑢 ∈𝐻𝑖,𝑣 ∈𝑆𝑖f(u,v)∀u∈Hi,v∈Si, and mark 𝑣v as a neighbor of 𝑢u if 𝑓(𝑢,𝑣) =1f(u,v)=1.
    4. For every 𝑢 ∈𝐻𝑖u∈Hi for which we haven't found 𝑘k neighbors yet, add 𝑢u back to 𝐿L.
Note
We can trivially solve this problem faster for 𝑘 =1k=1 by constructing a segment tree over 𝑌Y, doing dfs on it, and passing down elements of 𝑋X to one of the two children based on queries from 𝐷D constructed on elements from one of the two children.

Complexity Analysis

The cumulative time for building all the data structures will be 𝑂(⌈𝑚/𝐵⌉ ⋅𝑝(𝐵))O(⌈m/B⌉⋅p(B)).

For queries:

  1. At every 𝑆𝑖Si, we query 𝑄(𝑢,𝐷(𝑆𝑖)) ∀ 𝑢 ∈𝐿Q(u,D(Si))∀u∈L. Since |𝐿| ≤𝑛|L|≤n, this takes 𝑂(𝑛 ⋅⌈𝑚/𝐵⌉ ⋅𝑞(𝐵))O(n⋅⌈m/B⌉⋅q(B)) time.
  2. It's easy to see that every node 𝑢 ∈𝑋u∈X is added to 𝐻𝑖Hi for at most 𝑘k distinct values of 𝑖i. Every time a 𝑢u is added to 𝐻𝑖Hi, we compute 𝑓(𝑢,𝑣)f(u,v) for ≤𝐵≤B distinct values of 𝑣v. This takes 𝑂(𝑛 ⋅𝐵 ⋅𝑘 ⋅𝑥)O(n⋅B⋅k⋅x) time.

Therefore the total time taken is:

𝑂(𝑛⋅𝐵⋅𝑘⋅𝑥+⌈𝑚/𝐵⌉⋅(𝑝(𝐵)+𝑛⋅𝑞(𝐵)))O(n⋅B⋅k⋅x+⌈m/B⌉⋅(p(B)+n⋅q(B)))

The choice of 𝐵B is highly problem dependent, but in most setups where this idea could be used, I think we would have 𝑘 ⋘𝑛k⋘n and 𝑞q would be pretty fast. I recommend solving the example problem to understand why the complexity is decent if you think it is garbage.

Example Problems

1. CF-1957F2

You are given 𝑞q queries. In each query, you are given 5 integers, 𝑢1u1, 𝑣1v1, 𝑢2u2, 𝑣2v2, and 𝑘k. Denote the count of nodes with value 𝑐c on the path 𝑢1 →𝑣1u1→v1 with 𝑥𝑐xc, and the count of nodes with value 𝑐c on the path 𝑢2 →𝑣2u2→v2 with 𝑦𝑐yc. If there are 𝑧z such values of 𝑐c such that 𝑥𝑐 ≠𝑦𝑐xc≠yc, output any min(𝑧,𝑘)min(z,k) such values in any order.
