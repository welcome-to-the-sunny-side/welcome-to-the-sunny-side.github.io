Problem CF-2128F

Statement

You are given an undirected connected graph with 𝑛n nodes and 𝑚m edges. The weight wi of the 𝑖i-th edge is not yet decided and must be a real number between 𝑙𝑖li and 𝑟𝑖ri.

You are given a node 𝑘k. Determine if there exists a valid assignment of weights (𝑤1,…,𝑤𝑚)(w1,…,wm) such that:

  • 𝑙𝑖 ≤𝑤𝑖 ≤𝑟𝑖li≤wi≤ri for all 𝑖i

  • dis𝑤(1,𝑛) ≠dis𝑤(1,𝑘) +dis𝑤(𝑘,𝑛)disw(1,n)≠disw(1,k)+disw(k,n)

Constraints:

  • 4 ≤𝑛 ≤2000004≤n≤200000

  • 𝑛 −1 ≤𝑚 ≤200000n−1≤m≤200000

  • 2 ≤𝑘 ≤𝑛 −12≤k≤n−1

  • no self-loops

  • 1 ≤𝑙𝑖 ≤𝑟𝑖 ≤1091≤li≤ri≤109

Solution

It's easy to see that the problem requires us to check if there exists an assignment of weights for which the node 𝑘k doesn't lie on any shortest path from 11 to 𝑛n. Alternatively, the shortest path from 11 to 𝑛n must have a strictly smaller total weight than the shortest path from 11 to 𝑛n which contains the node 𝑘k.

Let's consider some shortest path in a valid assignment of weights 𝑤w and play around with the weight relations (with the hope of simplifying things). Let's consider a particular shortest path 𝑃P containing the edges indexed 𝑒1,𝑒2…𝑒𝑝e1,e2…ep (this will obviously (a) be a simple path with no repeated edges or nodes (b) not contain the node 𝑘k).

Observation 1:

For all 𝑒𝑖 ∉𝑃ei∉P, we can set 𝑤𝑒𝑖 =𝑟𝑒𝑖wei=rei without affecting the validity of 𝑤w.

Proof

Doing so doesn't affect the weight of 𝑃P and only potentially increases the weight of the paths from 11 to 𝑛n which go through 𝑘k. Since the shortest one amongst the latter was strictly worse than 𝑃P before these changes, the shortest one amongst the latter after these changes is also strictly worse.

Observation 2:

For all 𝑒𝑖 ∈𝑃ei∈P, we can set 𝑤𝑒𝑖 =𝑙𝑒𝑖wei=lei without affecting the validity of 𝑤w.

Proof

Consider a single change, on edge 𝑒𝑖ei. Let's say performing this change results in its weight decreasing by △△. This results in the total weight of 𝑃P decreasing by exactly △△ (since 𝑃P contains no repeated edges). We want to show that there can exist no shortest path through 𝑘k after this change. Paths from 11 to 𝑛n through 𝑘k can be classified into three categories:

  1. Paths that don't contain the edge 𝑒𝑖ei: they were worse than 𝑃P, and remain so.

  2. Paths that contain the edge 𝑒𝑖ei once: they were initially worse than 𝑃P, and their total edge weight is reduced by the same amount as 𝑃P, so they remain worse.

  3. Paths that contain the edge 𝑒𝑖ei multiple times: while they receive a greater decrease to their total weight than 𝑃P, simply cannot be the shortest paths from 11 to 𝑛n as they're not simple, and all edge weights are strictly positive.

A vague skeleton for a potential solution begins to take form: maybe we fix some simple path from 11 to 𝑛n, set the weights of all edges on it to 𝑙𝑒𝑖lei, all outside it to 𝑟𝑒𝑖rei, and check if:

  • It's the shortest path from 11 to 𝑛n.

  • Its total weight is strictly smaller than that of the shortest path from 11 to 𝑛n through 𝑘k.

We can observe that the first condition is actually unnecessary: it suffices to check for the second condition, because the second being satisfied implies that there's some path from 11 to 𝑛n with strictly smaller total weight than the shortest one through 𝑘k. For now, continue to assume that 𝑃P is a shortest path from 11 to 𝑛n.

Let us now look at the intersection between 𝑃P and the shortest path from 11 to 𝑛n through 𝑘k, 𝑃′P′.

This leap might feel a bit arbitrary to the passive reader, so the intuitive justification I provide is that since we reach nodes on 𝑃P in an optimal manner w.r.t. 11 and 𝑛n, (for any shortest path from 𝑠s to 𝑡t, the path from 𝑠s to any intermediate node 𝑝p is one of the shortest paths from 𝑠s to 𝑝p, and the path from 𝑡t to any intermediate node 𝑝p is one of the shortest paths from 𝑡t to 𝑝p), and that 𝑃P and 𝑃′P′ necessarily intersect at their extremes (11 and 𝑛n), one needs to "deviate" from 𝑃′P′ only to visit 𝑘k. A more formal justification follows.

Let the vertices on 𝑃′P′ be 𝑣1,𝑣2,…𝑣𝑞v1,v2,…vq. Define 𝑓(𝑢)f(u) to be 11 if the node 𝑢u lies on 𝑃P, and 00 otherwise.

Observation 3:

There exists some 𝑃′P′ (shortest path from 11 to 𝑛n through 𝑘k) such that the sequence 𝑆(𝑃′) =𝑓(𝑣𝑖) :1 ≤𝑖 ≤𝑞S(P′)=f(vi):1≤i≤q takes the following form: 11…1100…0011…1111…1100…0011…11 (ie. a non-empty segment of 11s, followed by a non-empty segment of 00s, followed by a non-empty segment of 11s).

Proof

  1. 𝑆(𝑃′)1 =1S(P′)1=1 as 𝑣1 =1,𝑓(1) =1v1=1,f(1)=1.

  2. 𝑆(𝑃′)𝑞 =1S(P′)q=1 as 𝑣𝑞 =𝑛,𝑓(𝑛) =1vq=n,f(n)=1.

  3. There exists some 𝑗 ∈(1,𝑞)j∈(1,q) such that 𝑣𝑗 =𝑘vj=k, and 𝑆(𝑃′)𝑗 =0S(P′)j=0 as 𝑓(𝑘) =0f(k)=0.

  4. Let us now consider some shortest path from 11 to 𝑛n through 𝑘k, 𝑅R and show that we can transform 𝑅R to 𝑃′P′ while still having the same weight.

    The first three points imply that the sequence 𝑆(𝑅)S(R) looks like 1…[arbitrary mix of 0s and 1s] 0 [arbitrary mix of 0s and 1s] 11…[arbitrary mix of 0s and 1s]0[arbitrary mix of 0s and 1s]1 (with the guaranteed 00 at position 𝑗j existing due to the guaranteed (and singular) existence of 𝑘k in 𝑅R). Now consider the closest 11s to 𝑆(𝑅)𝑗S(R)j to the left and right (both are guaranteed to exist as the first and last elements are 11s). Let their position be 𝑙l and 𝑟r respectively. Let the 𝑙l-th and 𝑟r-th nodes in 𝑅R be 𝑔g and ℎh respectively.

    Let's now construct the following path, 𝑅′R′:

    1. We go from 11 to 𝑔g through the same sub-path we do on 𝑃P (note that 𝑔g is guaranteed to exist in 𝑃P).

    2. We go from 𝑔g to ℎh through the same sub-path we do on 𝑅R (note that this ensures we go through 𝑘k).

    3. We go from ℎh to 𝑛n through the same sub-path we do on 𝑃P (note that ℎh is guaranteed to exist in 𝑃P).

    Claim 3.1:

    The total weight of 𝑅′R′ is not greater than that of 𝑅R.

    Proof:

    Consider the three subpaths that both 𝑅R and 𝑅′R′ can be divided into: 1 →𝑔 →ℎ →𝑛1→g→h→n. The second sub-path (𝑔 →ℎg→h) is the same in both 𝑅R and 𝑅′R′, and therefore has an equal contribution to the weight. Now, since 𝑃P is one of the shortest paths from 11 to 𝑛n, the sub-paths 1 →𝑔1→g and ℎ →𝑛h→n on 𝑃P are the shortest paths between those nodes, and therefore cannot have greater weights than their counter-parts in 𝑅R.

    Claim 3.2:

    𝑆(𝑅′) =𝑓(𝑣𝑖) :1 ≤𝑖 ≤𝑞S(R′)=f(vi):1≤i≤q takes the following form: 11…1100…0011…1111…1100…0011…11 (ie. a non-empty segment of 1s, followed by a non-empty segment of 0s, followed by a non-empty segment of 1s).

    Proof:

    Obvious.

    We have therefore showed the existence of a valid 𝑃′P′.

Anyways, how does all of this even help us? It helps us because it implies that if there exists a valid assignment of weights, then there exists a pair of paths 𝑃,𝑃′P,P′ (and the implicit assignment of weights 𝑤w defined by 𝑃P as mentioned above) such that:

  • 𝑃P is the shortest path from 11 to 𝑛n.
  • 𝑃′P′ is the shortest path from 11 to 𝑛n through 𝑘k, and satisfies that nice property we derived earlier (follows 𝑃P, only deviates once to visit 𝑘k, and then follows 𝑃P again).
  • 𝑃P has a smaller total weight than 𝑃′P′.

This is extremely convenient as we can now look at the smallest path from 11 to 𝑛n through 𝑘k by only considering the previously defined 𝑔g and ℎh on 𝑃P.

Let's now define 𝑑𝑘(𝑢)dk(u) to be the shortest distance between 𝑢u and 𝑘k when all the edge weights are set to 𝑟𝑒𝑖rei.

We observe that for a fixed 𝑃P, the shortest path from 11 to 𝑛n through 𝑘k has the weight:

min𝑔,ℎ∈𝑃(dis𝑤(1,𝑔)+𝑑𝑘(𝑔)+𝑑𝑘(ℎ)+dis𝑤(ℎ,𝑛))ming,h∈P(disw(1,g)+dk(g)+dk(h)+disw(h,n))

The only point of contention one may have with this formula is that for certain 𝑔g (or symmetrically ℎh), 𝑑𝑘(𝑔)dk(g) may not actually represent the shortest distance between 𝑔g and 𝑘k in the current path, as some edge weights set to 𝑟𝑒𝑖rei in the graph 𝑑𝑘dk is derived from may lie on 𝑃P here and consequently be set to 𝑙𝑒𝑖lei.

Observation 4:

The minimum for (1)(1) is produced by at least one pair 𝑔,ℎg,h for which both 𝑑𝑘(𝑔)dk(g) and 𝑑𝑘(ℎ)dk(h) are valid.

Proof

As we've already shown earlier, some optimal path through 𝑘k is going to travel along 𝑃P for some prefix, hop off it once, visit 𝑘k, and hop back onto 𝑃P for the remaining suffix. Those two "hop points" can be chosen as 𝑔g and ℎh to get the minimum for (1)(1).

Let's simplify things a bit for us now.

Observation 5

If (1)(1) is satisfied for any path 𝑃P without 𝑘k, then the weight assignment induced by 𝑃P is valid.

Proof

How does this relate to our original requirement of having 𝑃P be strictly shorter than 𝑃′P′? We now require:

min𝑔,ℎ∈𝑃(dis𝑤(1,𝑔)+𝑑𝑘(𝑔)+𝑑𝑘(ℎ)+dis𝑤(ℎ,𝑛))>dis𝑤(1,𝑛)ming,h∈P(disw(1,g)+dk(g)+dk(h)+disw(h,n))>disw(1,n) ⟹𝑑𝑘(𝑔)+𝑑𝑘(ℎ)>dis𝑃(𝑔,ℎ)∀𝑔,ℎ∈𝑃(1)(1)⟹dk(g)+dk(h)>disP(g,h)∀g,h∈P

dis𝑃(𝑔,ℎ)disP(g,h) just refers to the distance between 𝑔g and ℎh on 𝑃P here.

Alright, with all of that foreplay out of the way, how do we design an efficient algorithm that exploits these properties? All we care about is finding a path 𝑃P in the graph such that (1)(1) is satisfied for it.

Consider a simple line graph from 11 to 𝑛n. How would we check if the unique path from 11 to 𝑛n satisfies (1)(1)? Let's obviously assume that 𝑑𝑘dk has been precomputed.

Consider the following pseudo-code that does this:

p = nodes on the path from 1 to n
sat = true

for i from 1 to n:
    v = p[i]
    for j from 1 to i:
        u = p[j]
        if dk[u] + dk[v] <= dis_P(u, v):
            sat = false

This works in 𝑂(𝑛2)O(n2) (forget about the precomputation for now), but can we do better? We realize that the distance function dis𝑃(𝑢,𝑣)disP(u,v) has a rather "continuous" nature, and we can exploit this to do something similar to kadane's algorithm (just maintain the value of the extreme suffix).

This leads to the following 𝑂(𝑛)O(n) solution:

p = nodes on the path from 1 to n
sat = true
worst_suffix = -dk[p[1]]

for i from 2 to n:
    v = p[i]
    worst_suffix = max(worst_suffix + dis_P(p[i - 1], v), -dk[v])
    if dk[v] <= worst_suffix:
        sat = false

Alright, let's now consider doing this for arbitrary paths in a general graph.

We will try to incrementally build good paths from node 11 that have the potential to satisfy 11. What properties must such a potential path from 11 to 𝑢u satisfy?

  • It must not contain 𝑘k.
  • (1)(1) must obviously be satisfied for 𝑔,ℎg,h on this prefix path.
  • In addition, note that as long as (1)(1) is satisfied on this prefix, the only thing that will affect (1)(1) as we further extend this path is the analogous value of worst_suffix until now. It's easy to see that we should aim to minimise this value.

This trivially leads to the following 𝑂(𝑛 ⋅𝑚)O(n⋅m) algorithm (just have 𝑛n rounds (max number of nodes in 𝑃P) where you try to transition across every edge).

precompute dk using djikstras

opt[n]

opt[1] = -dk[1]
for u from 2 to n:
    opt[u] = inf

for round from 1 to n:
    nopt = opt
    for u from 1 to n:
        for [v, l, r] in adj[u]:
            if (u != k and v != k and dk[v] > opt[u] + l)
                nopt[v] = min(nopt[v], max(-dk[v], opt[u] + l))
    opt = nopt

if opt[n] != inf:
    valid assignment exists

To optimize this to 𝑂((𝑛 +𝑚)log⁡𝑛)O((n+m)log⁡n), we can simply observe that we can use a Djikstra's like approach here due to the monotonic nature of the transitions (due to strictly positive edge weights).
