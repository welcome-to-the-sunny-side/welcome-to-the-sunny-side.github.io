Problem CF-2056F2

Statement

A sequence 𝑎a of 𝑛n integers is called good iff the following condition holds:

  • Let 𝑐𝑛𝑡𝑥cntx be the number of occurrences of 𝑥x in the sequence 𝑎a.
  • For all pairs 0 ≤𝑖 <𝑗 <𝑚0≤i<j<m, at least one of the following must be true:
    • 𝑐𝑛𝑡𝑖 =0cnti=0
    • 𝑐𝑛𝑡𝑗 =0cntj=0
    • 𝑐𝑛𝑡𝑖 ≤𝑐𝑛𝑡𝑗cnti≤cntj

In other words, if both 𝑖i and 𝑗j are present in the sequence, then the number of occurrences of 𝑖i must be less than or equal to the number of occurrences of 𝑗j.

You are given integers 𝑛n and 𝑚m. Compute the bitwise XOR of the medians of all good sequences 𝑎a of length 𝑛n, where each element 𝑎𝑖ai satisfies 0 ≤𝑎𝑖 <𝑚0≤ai<m.

Constraints:

  • 𝑛 ≤2105n≤2105 (given to us in its binary form)
  • 𝑚 ≤109m≤109

Solution

I'm going to pick up right where I left off in the previous blog.

Notice the changes in this version - the constraints on 𝑘k and 𝑚m have both increased by orders of magnitude, rendering our previous methods of approach (particularly those that required superlinear time w.r.t. 𝑚m) useless.

Let's examine the algorithm we used earlier at a high level, and see if there are components vulnerable to optimization:

ans = 0
for median q from 0 to m - 1:
    par = 0
    for (# of unique elements) x from 1 to min(q + 1, k):
        if (C(q, x - 1) * f(k, x)) % 2 == 1
            par ^= 1
    if par == 1
        ans ^= q

Firstly, we cannot compute required values of 𝑓f trivially in 𝑂(𝑘2)O(k2) like we did earlier, but we can analyse the recurrence and realize that 𝑓(𝑖,𝑗) =1 ⟺ (𝑖 −𝑗)AND((𝑗 −1)/2) =0f(i,j)=1⟺(i−j)AND((j−1)/2)=0 (where ANDAND is the bitwise-AND operation). The proof for this is left as an exercise to the reader. We can therefore get rid of the 𝑂(𝑘2)O(k2) precomputation we were performing earlier, and look up values for 𝑓(𝑖,𝑗)f(i,j) in 𝑂(1)O(1).

Now, as we already know from the ideas introduced in the previous blog: ((𝑞𝑥−1) ≡1(mod2)) ⟺ ((𝑥 −1) is a submask of 𝑞)((qx−1)≡1(mod2))⟺((x−1) is a submask of q), so when iterating over the number of unique elements 𝑥x, we can simply ignore all 𝑥x where 𝑥 −1x−1 isn't a submask of 𝑞q. To make things more convenient, let's redefine 𝑥x to be the number of unique elements besides the median (just so we can say "𝑥x must be a submask of 𝑞q" instead of "𝑥 −1x−1 must be a submask of 𝑞q"). The algorithm now becomes:

ans = 0
for median q from 0 to m - 1:
    par = 0
    for submask x of q such that x < k:
        par ^= f(k, x + 1)
    if par == 1
        ans ^= q

It should not be difficult to spot some glaring redundancy here, namely the fact that parpar can be computed in an identical manner for several 𝑞q!

Why is this the case? Notice that while 𝑞q can be rather large, we limit the submasks 𝑥x to the range [0,𝑘)[0,k), where 𝑘k is at most 105105. This means that only the first 𝐿 =⌈log2⁡𝑘⌉L=⌈log2⁡k⌉ bits of 𝑞q determine whether 𝑥x is a submask of 𝑞q or not.

To avoid this redundancy, we can instead compute the value of parpar only once for every suffix mask (least significant bits) of 𝐿L bits (which is feasible since 2𝐿 ≈𝑂(𝑘)2L≈O(k)), and if it turns out to be 11, we know that we would have individually XOR'd the answer with 𝑞q for all 𝑞q which have this mask as a suffix in our original algorithm, so we can now just try to process all of those individual changes together! Note that we can also conveniently ignore the restriction that 𝑥 <𝑘x<k, and instead just let it be a submask of 2𝐿2L as 𝑓(𝑘,𝑥) =0f(k,x)=0 for 𝑥 >𝑘x>k in any case.

Our algorithm now reduces to the following:

ans = 0
for (median suffix mask) p from 0 to (2^L - 1):
    par = 0
    for submask x of p:
        par ^= f(k, x + 1)
    if par == 1
        ans ^= (q : (the first L bits of q = p))

Now, the problem decomposes to two easy and independent subproblems:

  1. Finding (⨁𝑥⊆𝑝𝑓(𝑘,𝑥 +1))∀𝑝 ∈[0,2𝐿)(⨁x⊆pf(k,x+1))∀p∈[0,2L) (here 𝑥 ⊆𝑝x⊆p means that 𝑥x is a submask of 𝑝p). This is a standard application of SOS DP, and warrants no further explanation from me.
  2. Finding (⨁𝑝⊆𝐿𝑞𝑞)∀𝑝 ∈[0,2𝐿)(⨁p⊆Lqq)∀p∈[0,2L). This can be done in 𝑂(1)O(1) but I hate digit analysis far too much to not have mindlessly bashed it in 𝑂(log32⁡𝑚)O(log23⁡m).

So our final solution runs in 𝑂(𝑘 ⋅(log2⁡𝑘 +log32⁡𝑚))O(k⋅(log2⁡k+log23⁡m)) and can be optimized to 𝑂(𝑘 ⋅log2⁡𝑘)O(k⋅log2⁡k) at the risk of one's sanity.

Code:

#include<bits/stdc++.h>
using namespace std;

signed main()
{
    ios_base::sync_with_stdio(false), cin.tie(NULL);
    int t = 1;
    cin >> t;
    while(t --)
    {
        int k, m;
        cin >> k >> m;

        string n;
        cin >> n;

        k = count(n.begin(), n.end(), '1');

        int L = 0;
        while((1 << (L)) <= k)
            ++ L;

        auto f = [&](int a, int b) -> int
        {
            if(a < b)
                return 0;
            return ((a - b) & ((b - 1) >> 1)) == 0;
        };

        vector<int> sos(1 << L);
        for(int p = 0; p < (1 << L); p ++)
            sos[p] = f(k, p + 1);
        for(int i = 0; i < L; i ++)
            for(int p = 0; p < (1 << L); p ++)
                if((1 << i) & p)
                    sos[p] ^= sos[p ^ (1 << i)];

        int ans = 0;
        for(int p = 0; p < (1 << L); p ++)
        {
            if(sos[p])
                if(p < m)
                {
                    int xorsum = 0;
                    // p0 p1 ... p(L-1) bit(L) bit(L+1) ... 
                    for(int b = L; b < 30; b ++)
                        if((1 << b) + p < m)
                        {
                            vector<int> bits;
                            for(int i = L; i < 30; i ++)
                                if(i != b)
                                    bits.push_back(i);
                            
                            int sz = bits.size();
                            int l = 0, r = (1 << sz) - 1, opt = 0;
                            while(l <= r)
                            {
                                int mid = (l + r)/2;

                                int sum = (1 << b) + p;
                                for(int i = 0; i < bits.size(); i ++)
                                    if((1 << i) & mid)
                                        sum += (1 << bits[i]);
                                
                                if(sum < m)
                                    opt = mid, l = mid + 1;
                                else
                                    r = mid - 1;
                            }

                            if((opt + 1) & 1)
                                xorsum ^= (1 << b);
                        }

                    {
                        vector<int> bits;
                        for(int i = L; i < 30; i ++)
                            bits.push_back(i);
                        
                        int sz = bits.size();
                        int l = 0, r = (1 << sz) - 1, opt = 0;
                        while(l <= r)
                        {
                            int mid = (l + r)/2;

                            int sum = 0;
                            for(int i = 0; i < bits.size(); i ++)
                                if((1 << i) & mid)
                                    sum += (1 << bits[i]);
                            
                            if(sum + p < m)
                                opt = mid, l = mid + 1;
                            else
                                r = mid - 1;
                        }

                        if((opt + 1) & 1)
                            xorsum ^= p;
                    }                    

                    ans ^= xorsum;
                }
        }
        cout << ans << endl;
    }
}
