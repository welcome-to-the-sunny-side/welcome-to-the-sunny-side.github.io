Solution

Firstly, it's time for me to admit that I never really bothered to learn how a fenwick tree internally works, due to almost always having preferred segment trees over them (only using them as a blackbox when trying to squeeze one of my cursed 𝑂(𝑛√𝑛log⁡𝑛)O(nnlog⁡n) implementations into the TL). Knowing this, the reader shall excuse me for spending some time understanding what's going on with lowbit⁡(𝑥)lowbit⁡(x).

Let's define lsb⁡(𝑥) =log2⁡(lowbit⁡(𝑥))lsb⁡(x)=log2⁡(lowbit⁡(x)) for convenience.

So, what does the sequence lowbit⁡(𝑥)lowbit⁡(x) even look like? It takes the following form:

1 2 1 4 1 2 1 8 1 2 1 4 1 2 1 16 ...

Clearly, lowbit⁡(𝑥)lowbit⁡(x) is simply the greatest power of 2 that divides 𝑥x, and any value of lowbit⁡(𝑥)lowbit⁡(x), say 𝑑d, repeats with a period of 𝑑d save for places where it gets "overridden" by greater values of 𝑑d.

Now, what form do the segments [𝑖 −lowbit⁡(𝑖) +1,𝑖][i−lowbit⁡(i)+1,i] take?

It isn't difficult to see that this structure is essentially just half a segment tree (to be more specific, it is what we would be left with upon deleting the segment corresponding to the right child of every node).

Here's an illustration that should make this clearer. The blue nodes (and their corresponding ranges) are the ones present in our structure, while the red ones aren't.

Let's give this thing a name, we'll call it a ghost segment tree (after the red ghost nodes/segments).

What are some useful properties of this structure?

  1. For all 𝑖i, lowbit⁡(𝑗) =lowbit⁡(𝑖 −lowbit⁡(𝑖) +𝑗)lowbit⁡(j)=lowbit⁡(i−lowbit⁡(i)+j) for 1 ≤𝑗 ≤lowbit⁡(𝑖)1≤j≤lowbit⁡(i). This simplifies analysis by a great deal, as we now need to only concern ourselves with prefixes of the lowbit⁡(𝑖)lowbit⁡(i) that have lengths which are some powers of two.
  2. Let's define cover⁡(𝑖)cover⁡(i) as the set of all 𝑗j where 𝑗 −lowbit⁡(𝑗) +1 ≤𝑖 ≤𝑗j−lowbit⁡(j)+1≤i≤j. Then lowbit⁡(𝑗1) ≠lowbit⁡(𝑗2) ∀ 𝑗1,𝑗2 ∈cover⁡(𝑖) :𝑗1 ≠𝑗2lowbit⁡(j1)≠lowbit⁡(j2)∀j1,j2∈cover⁡(i):j1≠j2.

How do these properties help us? Consider the first property, it implies that no matter what 𝑖i we choose, the minimal "subtree" of this "ghost segment tree" that contains the segment [𝑖 −lowbit⁡(𝑖) +1,𝑖][i−lowbit⁡(i)+1,i] will conveniently be isomorphic to the minimal subtree over the segment [1,lowbit⁡(𝑖)][1,lowbit⁡(i)]. This is extremely convenient because we now know that for any 𝑖i, the minimal subtree containing its segment is going to be a perfect binary tree of height lsb⁡(𝑖)lsb⁡(i) (well, as perfect as it can get with half of its nodes being ghost nodes, but you get the point), and we can use properties implied from this symmetry to design efficient algorithms.

Another useful property is that the leaf node corresponding to 𝑖i is the rightmost leaf in the minimal subtree on segment [𝑖 −lowbit⁡(𝑖) +1,𝑖][i−lowbit⁡(i)+1,i].

For instance, let's consider finding the sum over [𝑖 −lowbit⁡(𝑖) +1,𝑖][i−lowbit⁡(i)+1,i] for all 𝑖 ≤𝑛i≤n. Assume 𝑛 =8n=8, and look at the diagram above again.

A simple way to do this is the following:

  • We compute 𝑥(𝑖) =∑𝑖−lowbit⁡(𝑖)+1≤𝑗≤𝑖𝑎𝑗x(i)=∑i−lowbit⁡(i)+1≤j≤iaj in increasing order of 𝑖i.
  • We compute 𝑥(𝑖)x(i) in the following manner:
    • We begin at 𝑣 =v= the leaf node corresponding to 𝑖i, with 𝑥(𝑖) =𝑎𝑖x(i)=ai.
    • Until 𝑣 ≠𝑟v≠r, where 𝑟r is the root node of the minimal subtree containing [𝑖 −lowbit⁡(𝑖) +1,𝑖][i−lowbit⁡(i)+1,i]:
      • Set 𝑣v to the parent of 𝑣v.
      • Let lclc be the rightmost leaf in the subtree of the left child of 𝑣v. Add 𝑥(lc)x(lc) to 𝑥(𝑖)x(i).

It's easy to see that this is valid because the rightmost leaf in any subtree corresponds to a segment that covers all the leaf nodes in that subtree. This algorithm takes 𝑂(𝑛log⁡𝑛)O(nlog⁡n) time, as we traverse to 𝑣v's parent at most 𝑂(log⁡𝑛)O(log⁡n) times for each 𝑖i.

For the sake of brevity in the coming sections, we define 𝐶(𝑖)C(i) to be the set of all lclc that we touch when we run this algorithm for 𝑖i.

The final solution takes the following form:

L = ceil(log2(n))
coeff2_t[L + 1] #compute this in whatever manner you'd like

a_0[n + 1]      #initial values (to be recovered)
a_t[n + 1]      #final values (at time t)
dp[n + 1][L + 1]    #dp[i][c] = sum(a_0[j]) for j : S(i, j) = c

for i from 1 to n:
    compute C(i) in O(log(n))
    for y in C(i)
        for c from 1 to L
            dp[i][c] += dp[y][c - 1]

    a_0[i] = a_t[i]
    for c from 1 to L
        a_0[i] -= dp[i][c] * coeff2_t[c]

    dp[i][0] = a_0[i]
