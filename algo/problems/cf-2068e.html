Problem CF-2068E

Statement

FC Porto and SL Benfica are the two largest football teams in Portugal. Naturally, when the two play each other, a lot of people travel from all over the country to watch the game. This includes the Benfica supporters' club, which is going to travel from Lisbon to Porto to watch the upcoming game. To avoid tensions between them and the Porto supporters' club, the national police want to delay their arrival to Porto as much as they can.

The road network in Portugal can be modelled as a simple, undirected, unweighted, connected graph with 𝑛n vertices and 𝑚m edges, where vertices represent towns and edges represent roads. Vertex 1 corresponds to Lisbon, i.e., the starting vertex of the supporters' club, and vertex 𝑛n is Porto, i.e., the destination vertex of the supporters' club. The supporters' club wants to minimize the number of roads they take to reach Porto.

The police are following the supporters' club carefully, and so they always know where they are. To delay their arrival, at any point the police can pick exactly one road and block it, as long as the supporters' club isn't currently traversing it. They can do this exactly once, and once they do that, the road is blocked forever. Once the police block a road, the supporters' club immediately learns that that road is blocked, and they can change their route however they prefer. Furthermore, the supporters' club knows that the police are planning on blocking some road and can plan their route accordingly.

Assuming that both the supporters' club and the police always make optimal choices, determine the minimum number of roads the supporters' club needs to traverse to go from Lisbon to Porto. If the police can block the supporters' club from ever reaching Porto, then output −1.

Constraints:

  • 𝑛 ≤2 ⋅105n≤2⋅105
  • 𝑚 ≤2 ⋅105m≤2⋅105

Solution

I'll refer to the party traversing the graph from 11 to 𝑛n as player 𝐴A and the other as player 𝐵B.

Let's try to think of optimal strategies for 𝐴A and 𝐵B.

When trying to analyse the situation by mentally simulating some naive strategies, one runs into a sort of "chicken and egg" problem that is common in game-theoretic problems like these - the optimal move for 𝐴A at some state depends on the optimal move performed by 𝐵B before it, which in turn depends on the optimal move performed by 𝐴A before it, and so on, leading to a lack of "fixed points" in the timeline to build something concrete upon.

Consider a naive strategy: What if 𝐴A just always follows the shortest path in the current graph to the destination?

Now consider the following graph:

If 𝐴A tries to take the upper path (1 →2 →61→2→6), 𝐵B deletes the edge 2 →62→6 when 𝐴A reaches 22, and 𝐴A then has to backtrack and go to 66 through the path 2 →1 →3 →4 →62→1→3→4→6, having taken 55 steps in total.

However, if we go down the lower path instead, 𝐵B has two equally optimal moves, which both lead to a path length of 44:

  1. Delete edge (3,4)(3,4) after 𝐴A traverses the edge 1 →31→3. 𝐴A then takes the path 3 →1 →2 →63→1→2→6.
  2. If 𝐵B doesn't do the above, then 𝐴A traverses the edge 3 →43→4 and 𝐵B deletes the edge (4,6)(4,6). 𝐴A then goes to 66 via 4 →5 →64→5→6.

So the "always follow the shortest path" strategy is clearly not optimal for 𝐴A. We can however note that once 𝐵B performs his singular move, it's obviously optimal for 𝐴A to take the shortest path in this modified graph from his current position to the destination.

Notice that if 𝐴A reaches some node 𝑢u without 𝐵B already having performed his move, then the moves performed after that moment (𝐴A reaching 𝑢u) are totally independent of those before. Let's define 𝑡(𝑢)t(u) to be the length of the path traversed by 𝐴A after reaching 𝑢u if it reaches this position without 𝐵B having already performed his move. The final answer is clearly 𝑡(1)t(1).

Some more definitions:

  • 𝐺(𝑉,𝐸)G(V,E) - the graph we operate upon.
  • dis𝐸′⁡(𝑢,𝑣)disE′⁡(u,v) shortest distance between the nodes 𝑢u and 𝑣v in the graph 𝐺(𝑉,𝐸′)G(V,E′).

Now, can we compute 𝑡(𝑢)t(u) assuming all 𝑡(𝑣) :𝑣 ≠𝑢t(v):v≠u are available to us?

There are two branches, based on what 𝐵B does after 𝐴A reaches 𝑢u:

  1. 𝐵B deletes some edge right after we reach 𝑢u. Which edge would 𝐵B delete in this case? Some edge (𝑥,𝑦)(x,y) that maximises dis𝐸∖{(𝑥,𝑦)}⁡(𝑢,𝑛)disE∖{(x,y)}⁡(u,n).
  2. 𝐵B stalls and decides to delete an edge later. In this case, 𝐴A simply moves to arg⁡min(𝑢,𝑣)∈𝐸𝑡(𝑣)arg⁡min(u,v)∈Et(v), and we have 𝑡(𝑢) =1 +min(𝑢,𝑣)∈𝐸(𝑡(𝑣))t(u)=1+min(u,v)∈E(t(v)).

We therefore have:

𝑡(𝑢)=max(max(𝑢,𝑣)∈𝐸(dis𝐸∖{(𝑢,𝑣)}⁡(𝑢,𝑛)),1+min(𝑢,𝑣)∈𝐸(𝑡(𝑣)))t(u)=max(max(u,v)∈E(disE∖{(u,v)}⁡(u,n)),1+min(u,v)∈E(t(v)))

The first term in the outermost max is clearly problematic, as it requires the consideration of way too many edges, along with a computationally unfriendly function (shortest path from a source after the deletion of an edge), so let's think a bit more about the edges we may need to delete.

Clearly, the optimal edge (𝑥,𝑦)(x,y) that 𝐵B deletes needs to lie on some shortest path from 𝑢u to 𝑛n, as we would otherwise always have dis𝐸∖{(𝑥,𝑦)}⁡(𝑢,𝑛) =dis𝐸⁡(𝑢,𝑛)disE∖{(x,y)}⁡(u,n)=disE⁡(u,n), which is the worst possible outcome for 𝐵B. To be more accurate, if the edge (𝑥,𝑦)(x,y) doesn't lie on all shortest paths from (𝑢,𝑛)(u,n), we'll always have dis𝐸∖{(𝑥,𝑦)}⁡(𝑢,𝑛) =dis𝐸⁡(𝑢,𝑛)disE∖{(x,y)}⁡(u,n)=disE⁡(u,n).

So if there's no common edge shared between all shortest paths, we need not bother with the first term, but what if there is? Trying to optimally choose one ends up being rather cancerous once you think about it, and no sub-linear way presents itself quickly.

Notice that while trying to prune the set of potentially deleted edges 𝐷D above, we only considered the restriction imposed upon us after entering branch 1 (ie. when we know that 𝐵B definitely makes a move), but we should also consider requirements for entering branch 11 in the first place (ie. edges for which it's more optimal for 𝐵B to stall and delete later as opposed to just now).

What if (𝑥,𝑦)(x,y) is "far away" from 𝐴A's current position 𝑢u? One gets the intuitive sense that deleting (𝑥,𝑦)(x,y) when 𝐴A is just at 𝑢u might serve as a sort of "early warning" and prevent it from doing some backtracking that it otherwise would have.

The intuitive hope is that deleting later leads to a longer path due to 𝐴A "receiving a surprise (that it was already expecting) as late as possible". The image below attempts to show the picture in my mind when at this stage on the path to the solution.

Upon some further thought, one realizes that it's never optimal to delete some edge (𝑥,𝑦)(x,y) if it's not incident to 𝑢u.

Proof
Let's say 𝐴A is at 𝑢u and 𝐵B is considering some edge (𝑥,𝑦)(x,y) which is not incident to 𝑢u.

Let's say 𝐵B doesn't delete it now.

  • If at some point of time in the future, 𝐴A reaches 𝑥x (or WLOG 𝑦y), 𝐵B deletes (𝑥,𝑦)(x,y) immediately afterwards. 𝐴A then goes from 𝑥x to 𝑛n. This leads to it taking a path 𝑢 →𝑥 →𝑛u→x→n (which necessarily doesn't include the edge (𝑥,𝑦)(x,y)), which is at least as long as any path it could have taken from 𝑢u to 𝑛n without the edge (𝑥,𝑦)(x,y) if 𝐵B deleted the edge immediately after it reaching 𝑢u.
  • Otherwise, if 𝐴A never even visits 𝑥x (or 𝑦y) in the future, then deleting (𝑥,𝑦)(x,y) wouldn't have been (strictly) optimal in the first place.

So we now know that if 𝐵B chooses to delete an edge after 𝐴A reaches 𝑢u, it's going to be some edge (𝑢,𝑣)(u,v) that lies on at least one shortest path from 𝑢u to 𝑛n (if there are multiple such edges, then deletion is pointless as discussed before).

Define 𝑓(𝑢)f(u) to be the length of the shortest path from 𝑢u to 𝑛n if we delete one edge (𝑢,𝑣)(u,v) which lies on some shortest path from 𝑢u to 𝑛n in the original graph.

Since this seems like a standard subproblem, let's assume that we know how to solve this for now, and return to the expression:

𝑡(𝑢)=max(max(𝑢,𝑣)∈𝐸(dis𝐸∖{(𝑢,𝑣)}⁡(𝑢,𝑛)),1+min(𝑢,𝑣)∈𝐸(𝑡(𝑣)))t(u)=max(max(u,v)∈E(disE∖{(u,v)}⁡(u,n)),1+min(u,v)∈E(t(v)))

⟹𝑡(𝑢)=max(𝑓(𝑢),1+min(𝑢,𝑣)∈𝐸(𝑡(𝑣)))⟹t(u)=max(f(u),1+min(u,v)∈E(t(v)))

Clearly, values in 𝑡t have interdependence, but we luckily don't have to deal with cyclic dependencies as each 𝑢u depends only upon the singular adjacent node 𝑣v which has the minimum value of 𝑡(𝑣)t(v). This is reminiscent of dijkstra's and we can indeed use it here in the following manner:

precompute f[n]

initialize t[n] with t[i] = inf
t[n] = 0

set<pair<int, int>> q
q.push({t[n], n})

while(!q.empty()):
    int u = (*q.begin()).second
    q.erase(q.begin())

    for v in adj[u]:
        nx = max(1 + t[u], f[v])
        if(nx < tv):
            q.erase({t[v], v})
            t[v] = nx
            q.insert({t[v], v})

ans = t[1]

Let's return to the subproblem we assumed to be solvable earlier. We consider the BFS-DAG of the given graph assuming the source to be 𝑛n.

Definition of the BFS-DAG
We group nodes into levels based on their distance from the source.

Then, it's easy to see that for every edge (𝑢,𝑣)(u,v), we have |level𝑢 −level𝑣⁡| ≤1|levelu−levelv⁡|≤1.

Characterization of edges:

  • level𝑢 −level𝑣 =0levelu−levelv=0 : cross edge
  • level𝑢 −level𝑣 =1levelu−levelv=1 : back edge
  • level𝑢 −level𝑣 = −1levelu−levelv=−1 : forward edge

Here's an accompanying visual:

Notice that:

  1. If some node 𝑢u has multiple back-edges (𝑢,𝑣)(u,v), then 𝑓(𝑢) =dis𝐸⁡(𝑢,𝑛)f(u)=disE⁡(u,n) (for example, 𝑢 =5u=5 in the given image).
  2. If a node 𝑢u has only one back-edge but has some cross-edge (𝑢,𝑣)(u,v), then 𝑓(𝑢) =dis𝐸⁡(𝑢,𝑛) +1f(u)=disE⁡(u,n)+1 (for example, 𝑢 =13u=13 in the given image).

Let's consider the complement of the above two cases: we have a node 𝑢u with a single back-edge (𝑢,𝑣)(u,v) and no cross-edges incident to it (for example, 𝑢 =10u=10 in the given image).

𝑓(𝑢)f(u) is simply the shortest distance from 𝑢u to 𝑛n after having deleted the back-edge (𝑢,𝑣)(u,v). Clearly, this new shortest path is going to take the following form:

  • We travel down to some node 𝑗j (reachable from 𝑢u) such that 𝑗j has a cross-edge or back-edge (𝑗,𝑘)(j,k) such that 𝑘k isn't reachable from 𝑢u.
  • We take the back/cross-edge and then go from 𝑘k to 𝑛n.

This path will have a length of (level𝑗 −level𝑢) +level𝑗 +cross =2 ⋅level𝑗 −level𝑢 +cross(levelj−levelu)+levelj+cross=2⋅levelj−levelu+cross (where cross =1cross=1 if we take a cross-edge and 0 otherwise).

This implies that it's optimal to go to nodes with the lowest levels with such back/cross edges, and then prefer back-edges over cross-edges amongst these nodes.

Now, we don't really need to make any further simplifications as this sub-problem can be solved with some ugly small-to-large merging, but we can simplify it by a great deal.

Let's consider the BFS-Tree instead (a sub-graph of the BFS-DAG with no cross-edges and with each node having only one back-edge). The motivation for this is that it's much easier to work with trees then DAGs.

What's the problem with dealing with this BFS-Tree now? It's that some nodes that are reachable from 𝑢u in the BFS-DAG potentially don't lie within its subtree now.

However, we observe that any node 𝑗j that's reachable from 𝑢u in the BFS-DAG but doesn't lie within its subtree in the BFS-Tree is a potential 𝑗j (as it's going to have a path to 𝑛n that doesn't involve the edge (𝑢,𝑣)(u,v)).

Further, if some such 𝑗j isn't in the subtree of 𝑢u, we only need to consider it if there exists some edge (𝑝,𝑗)(p,j) such that 𝑝p lies in the subtree of 𝑢u (as it will otherwise be strictly suboptimal).

This leads to the following solution (I'm only giving a rough outline as I'm tired):

  • Build an euler tour on an arbitrary BFS-Tree.
  • For every node, compute the following six values:
    • lowest in-time cross-edge
    • lowest in-time back-edge
    • lowest in-time forward-edge
    • greatest in-time cross-edge
    • greatest in-time back-edge
    • greatest in-time forward-edge
  • Build a merge sort tree on the euler tour such that for every node 𝑢u, you store the aforementioned six things (in the form of pairs - (time,level𝑢 +constant)(time,levelu+constant), where timetime is one of the six values and constantconstant is dependent on the kind of edge being considered) at the leaf-node in the merge-sort tree at the in-time of 𝑢u. The rest of the merge-sort tree is built using the pairs at these leaf nodes.
  • To find the optimal 𝑗j for some node 𝑢u, you simply need to perform a rectangle query over [tin𝑢,tout𝑢][tinu,toutu] in this merge-sort tree to find a pair that (a) has first element outside [tin𝑢,tout𝑢][tinu,toutu] (b) has the smallest possible value of the second element. There are a couple of edge cases though (for example, the back-edge (𝑢,𝑣)(u,v) might result in a false-positive), so deal with them in whatever manner you find convenient.

And oh, the case where the answer is −1−1 is trivial, and is left as an exercise to the reader.
