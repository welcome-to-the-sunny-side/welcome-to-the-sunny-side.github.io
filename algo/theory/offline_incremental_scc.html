Hello, in this blog I'll explain the algorithm from this Radewoosh blog. The linked blog is understandable and well-written (and honestly, this idea can be in summarized in one line as "dnc over timeline") but it's a bit informal and I feel like writing something, hence this blog.

Problem

We are going to learn to maintain information about SCCs in a directed graph when have a problem with the following general structure:

Given an initially empty digraph 𝐺G, and a list of 𝑚m directed edges 𝐸E that are sequentially added to the graph, we need to answer queries of the following form: Find some information about SCCs in 𝐺G after the first 𝑖i edges are added

Some specific examples of queries would be:

  1. Find the smallest 𝑖i such that 𝑢u and 𝑣v belong to the same SCC after the first 𝑖i edges are added.
  2. Find the size of the SCC containing node 𝑢u after 𝑖i edges are added.

Note: As the title suggests, the idea described here is only applicable when we are allowed to process the queries offline.

Observations

Notation: Define 𝑆(𝑢,𝑖)S(u,i) to be the set of nodes in the SCC of node 𝑢u after the addition of the first 𝑖i edges to 𝐺G

The entire algorithm is based around a trivial observation:

For every pair of nodes (𝑢,𝑣)(u,v) we have, (𝑆(𝑢,𝑗) ≠𝑆(𝑣,𝑗)) ⟹ (𝑆(𝑢,𝑘) ≠𝑆(𝑣,𝑘))∀𝑘 ≤𝑗(S(u,j)≠S(v,j))⟹(S(u,k)≠S(v,k))∀k≤j.

Therefore, for every edge 𝐸𝑖 =(𝑢 →𝑣)Ei=(u→v), we define 𝑡𝑖 =arg⁡min𝑗(𝑆(𝑢,𝑗)=𝑆(𝑣,𝑗))ti=arg⁡minj(S(u,j)=S(v,j)) (and trivially infinite if they are never equal). One can observe that the presence of 𝐸𝑖Ei in 𝐺G doesn't affect the structure of any SCC until the the first 𝑡𝑖ti edges are added.

Algorithm

Pre-Processing

We will be doing DnC over the timeline of addition of edges (ie, [1,𝑚][1,m]) with a recursive function of the form 𝑓(𝑙,𝑟,edge list)f(l,r,edge list). For every call 𝑓(𝑙,𝑟,edge list)f(l,r,edge list), our edge listedge list will contain all edges 𝐸𝑖Ei for which 𝑙 ≤𝑡𝑖 ≤𝑟l≤ti≤r.

Let us look at what we do in the first call, 𝑓(1,𝑚,edge list)f(1,m,edge list) to understand what the generalized recursive call will be doing:

  1. Define mid =(1 +𝑚)/2mid=(1+m)/2. We add all edges 𝐸𝑖 :𝑖 ≤midEi:i≤mid to our initially empty graph and find SCCs induced by these edges. This can be done in 𝑂(𝑥)O(x) time where 𝑥x is the number of edges.
  2. Store information about SCCs/answer queries.
  3. For every edge 𝐸𝑖 =(𝑢 →𝑣) :𝑖 ≤midEi=(u→v):i≤mid, if SCC𝑢 =SCC𝑣SCCu=SCCv, then we can deduce that 𝑡𝑖 ≤(1 +𝑛)/2ti≤(1+n)/2. Otherwise, 𝑡𝑖 >midti>mid. Separate these edges into two groups G1G1 and G2G2 respectively. Add all edges 𝐸𝑖 :𝑖 >midEi:i>mid to G2G2.
  4. Call 𝑓(1,mid −1,G1)f(1,mid−1,G1).
  5. Once we return from this call, compress all the SCCs induced by the addition of edges in G1G1.
  6. Call 𝑓(mid +1,𝑚,G2)f(mid+1,m,G2). **Remember, this call must operate on the compressed graph.

Notice that when we execute 𝑓(𝑙,𝑟,edge list)f(l,r,edge list), it is essential that we perform the computation within it (finding SCCs induced by edge listedge list, checking if endpoints of edges belong to the same SCC, etc.) upon the compressed graph induced by all edges 𝐸𝑖 :𝑡𝑖 <𝑙Ei:ti<l. This can be done easily by maintaining a global graph 𝐺G, and performing compressions introduced by edge listedge list of 𝑓(𝑙,𝑟,edge list)f(l,r,edge list) when we return from this function (therefore, step 55 will actually be performed by 𝑓(1,mid −1,G1)f(1,mid−1,G1) and the calls in its subtree before they return).

The pseudo code for our algorithm takes the following form:

create an empty graph G with n nodes

def f(l, r, edge list):

    mid = (l + r)/2

    initialize SCC structure from G
    for every edge E[i] = (u -> v) in edge list:
        if(i <= mid)
            add (u -> v) to SCC structure

    compute SCCs
    
    problem specific stuff (storing info/answering queries)

    initialize empty edge lists G1 and G2
    for every edge E[i] = (u -> v) in edge list:
        if(i <= mid):
            if(SCC[u] = SCC[v])
                add E[i] to G1
            else
                add E[i] to G2
        else
            add E[i] to G2

    f(l, mid - 1, G1)
    f(mid + 1, r, G2)
    
    for every SCC induced by G1:
        compress SCC into a single node in G
enddef

f(1, m, edge list)

Answering Queries

This is quite problem-dependent. I have only seen a couple of problems which use this idea so I will just describe two ways of answering queries that I know of:

Queries based on number of edges added

These queries are of the form:

Find some information about the SCCs of a graph after 𝑖i edges are added.

Such queries can be answered by maintaining SCCs using DSU/Small-to-Large merging/(some other ds) as we go through the recursion in a way such that after performing the computation for 𝑓(𝑙,𝑟,edge list)f(l,r,edge list), all information about SCCs after adding the first (𝑙 +𝑟)/2(l+r)/2 edges will be queryable from our DS. We then answer all queries with 𝑖 =(𝑙 +𝑟)/2i=(l+r)/2.

Note: This is possible because if the SCC compression for 𝑓(𝑙1,𝑟1,edge list1)f(l1,r1,edge list1) is done before the SCC compression for 𝑓(𝑙2,𝑟2,edge list2)f(l2,r2,edge list2), then we have either (𝑙1 ≤𝑙2 and 𝑟1 ≤𝑟2)(l1≤l2 and r1≤r2) or (𝑙2 ≤𝑙1 and 𝑟1 ≤𝑟2)(l2≤l1 and r1≤r2). Therefore, SCCs only expand(unite) as we recurse through the calls.

Queries based on nodes

This is a somewhat non-trivial technique, which can be used to answer queries like:

Find the smallest 𝑖i such that nodes 𝑢u and 𝑣v belong to the same SCC after the first 𝑖i edges are added to 𝐺G

We solve it in the following way:

  1. We maintain an initially empty undirected weighted graph 𝑈U.
  2. At every call 𝑓(𝑙,𝑟,edge list)f(l,r,edge list), for every edge 𝐸𝑖 =(𝑢 →𝑣) ∈G1Ei=(u→v)∈G1, we add an edge (𝑢,𝑣)(u,v) with weight (𝑙 +𝑟)/2(l+r)/2 to 𝑈U.
  3. Finally, 𝑈U contains 𝑂(𝑚log2⁡𝑚)O(mlog2⁡m) edges, with weights ≤𝑚≤m.
  4. To answer a query for a pair of nodes (𝑢,𝑣)(u,v), one can observe that the problem is equivalent to finding the minimized maximum weight edge on any path between 𝑢u and 𝑣v in 𝑈U. This can be done by constructing the MST of 𝑈U and answering path maximum queries.

Note: Since all edges in 𝑈U have weight ≤𝑚≤m, we can avoid sorting its edge list and simply iterate over edge weights (in kruskals) to find the MST and get rid of a log factor, allowing construction of the MST in 𝑂(𝑚log2⁡𝑚)O(mlog2⁡m).

Complexity Analysis

Since we split apart edge listedge list into two disjoint groups G1G1 and G2G2 in every call 𝑓(𝑙,𝑟,edge list)f(l,r,edge list), this ensures that every edge occurs exactly once on every level of the recursion. For every call 𝑓(𝑙,𝑟,edge list)f(l,r,edge list), we perform a 𝑂(|edge list|)O(|edge list|) computation. So on every level, we perform a 𝑂(∑𝑓(𝑙,𝑟,edge list)(|edge list|)) =𝑂(𝑚)O(∑f(l,r,edge list)(|edge list|))=O(m) computation. There are log2⁡(𝑚)log2⁡(m) levels of the recursion, so our pre-processing algorithm works in 𝑂(𝑚log2⁡𝑚)O(mlog2⁡m).

The time taken for answering queries is problem dependent.
