Hello, in this blog I'll share a funny way to construct a suffix tree in 𝑂(𝑛log2⁡𝑛)O(nlog2⁡n) time, for a given string 𝑆S of length 𝑛n. I am going to call the underlying idea the "Leader Split Trick". It can probably be used to solve other problems too.

Problem

A suffix tree of a string 𝑆S is a radix tree constructed from all the suffixes of 𝑆S. It's easy to see that it has 𝑂(𝑛)O(n) nodes. It can be constructed in 𝑂(𝑛)O(n) using this.

I am going to share a simple and practically useless way of building it in a worse time complexity, 𝑂(𝑛log2⁡𝑛)O(nlog2⁡n).

Algorithm

Notation
  • When I refer to "suffix 𝑖i" ahead, I mean the suffix 𝑆[𝑖,𝑛]S[i,n].
  • 𝑙𝑖li is the leaf node corresponding to suffix 𝑖i in the final suffix tree.

Initially, we start with an empty tree (with a virtual root node), and a set 𝐺G of all suffixes from 11 to 𝑛n, these suffixes will be stored in the form of their starting index.

It's easy to see that the paths from the root node to 𝑙𝑢∀(𝑢 ∈𝐺)lu∀(u∈G) will share some common prefix till an internal node 𝑠𝐺sG, after which these paths will split apart along some downward edges of the internal node. Let's define 𝑑𝐺dG to be the longest common prefix across the paths (root,𝑙𝑢)∀𝑢 ∈𝐺(root,lu)∀u∈G.

Our algorithm will essentially do the following:

  1. Find 𝑑𝐺dG.
  2. Split apart 𝐺G into disjoint subsets 𝐺′G′ (each subset 𝐺′G′ will have suffixes whose leaves lie in the subtree of a unique child node of 𝑠𝐺sG).
  3. Solve the problem recursively for each subset, and add an edge in the suffix tree from 𝑠𝐺sG to 𝑠𝐺′sG′ for every 𝐺′G′.

Now, we define a recursive function 𝑓(𝐺,𝐿,dep,dis)f(G,L,dep,dis).

Definitions
  • 𝐺G : a set of suffixes (represented by starting indices)
  • 𝐿L : "leader" element (possibly undefined, in which case it will be "null")
  • depdep : depth of 𝑠𝐺𝑝sGp (the internal node of the parent call).
  • disdis : sorted list of integers (possibly undefined).

In each call, 𝑓(𝐺,𝐿,dep,dis)f(G,L,dep,dis), we do the following:

  1. If the "Leader" element 𝐿L is undefined:
    1. Set 𝐿L to a random element of 𝐺G.
    2. For every suffix 𝑖 ∈𝐺i∈G, find dis[i]dis[i], the longest common prefix of the suffixes 𝑖i and 𝐿L. This can be done in 𝑂(|𝐺| ⋅log⁡𝑛)O(|G|⋅log⁡n) using binary search + hashing. We store disdis in a sorted manner.
  2. Let 𝑚m be the minimum value in dis[]dis[]. It's easy to see that the internal node created from splitting 𝐺G will occur at depth dep +𝑚dep+m. We create 𝑠𝐺sG, and add an edge corresponding to the substring 𝑆[𝐿 +𝑑𝑒𝑝 +1,𝐿 +dep +𝑚]S[L+dep+1,L+dep+m] from 𝑠𝐺𝑝sGp to 𝑠𝐺sG.
  3. Now, we delete all suffixes 𝑖 ∈𝐺 :dis[i] =𝑚i∈G:dis[i]=m, from 𝐺G (and their corresponding elements from disdis), and group them into disjoint subsets based on the character 𝑆𝑖+dep+𝑚+1Si+dep+m+1 for suffix 𝑖i (basically the next character after the internal node).
  4. We call 𝑓(𝐺′,null,dep +𝑚,null)f(G′,null,dep+m,null) for every newly created subset 𝐺′G′, and also call 𝑓(𝐺,𝐿,dep + m,dis)f(G,L,dep + m,dis) for the modified subset 𝐺G.

Note: There might be some off-by-one errors.

Complexity Analysis

Consider the following problem:

We have 𝑛n singleton sets, and are given some set merge operations. When merging sets 𝐴A and 𝐵B, we merge 𝐵B to 𝐴A with probability |𝐴||𝐴|+|𝐵||A||A|+|B| and 𝐴A to 𝐵B with the probability |𝐵||𝐴|+|𝐵||B||A|+|B|.

The above problem is computationally equivalent to Randomized Quicksort, which has an expected time complexity of 𝑂(𝑛log⁡𝑛)O(nlog⁡n).

It's not difficult to see that our split operations are simply the operations that will occur in the above problem in a reversed manner (Formally, we can define a bijective relationship between the two sets of operations, such that related sets of operations will occur with the same probability) . Therefore, the time taken by all the split operations is 𝑂(𝑛log⁡𝑛)O(nlog⁡n).

However, every time we perform a split operation (merge in reverse), we also compute disdis for the child set 𝐶C (which gets merged into the parent set), and that takes 𝑂(|𝐶|log⁡𝑛)O(|C|log⁡n) time. Thus, our entire algorithm has an expected time complexity of 𝑂(𝑛log2⁡𝑛)O(nlog2⁡n).
